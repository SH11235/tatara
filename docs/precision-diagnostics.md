# FT precision diagnostics

For a native CUDA LayerStack training command, append:

```text
--precision-steps 1,2441600,7324800 --precision-samples 1024 --precision-seed 20260913
```

Steps are absolute, one-based optimizer step counts, including the count restored
from a raw checkpoint. Only listed steps that are actually executed produce a
`[precision]` JSON line. There is no implicit diagnostic at startup or checkpoint
load. For a scratch run, the last step of superbatch S is S times
`--batches-per-superbatch`; on resume, use the saved optimizer count and the number
of subsequently consumed batches. The options are global and can precede or follow
the `layerstack` subcommand. The default is OFF (no `--precision-steps`).

Support: native CUDA host/backend, LayerStack, FP32 or scaled FP16 FT moments,
with or without the FT FP16 forward copy and FT factorizer. Simple, cuda-oxide,
and oxide-parity builds reject the option. This observes FT weights, not bias,
dense state, TF32 arithmetic, QAT, export quantization, or dFT storage. The existing
`--monitor-fp16-clamps` remains the separate dFT cap metric with its original meaning.

## Sampling and cost

The sample is a uniform sample without replacement of flattened training FT
elements, generated by SplitMix64 with rejection sampling and sorted indices.
It is fixed across sampled steps; the seed does not consume training RNG state.
The size is min(requested size, FT element count), with a requested limit of 65536.
The population includes both base and virtual rows, and every neuron in each row.
The report partitions that same sample into `base` and `virtual`; the latter may
be small or empty. It is not an activity-weighted or stratified sample. The same
seed at different widths does not imply corresponding neurons or features.

Each JSON record has `scope=single_optimizer_step`: all counters, maxima and sums
are for that step alone, never cumulative or interpolated over skipped steps.
`population_elements`, `base_elements`, `ft_out`, `sample_count`, seed, precision
scales, factorization and Lookahead phase describe the observation conditions.

OFF allocates no diagnostic device buffers and launches no diagnostic kernels or
readbacks. An unselected step uses the ordinary optimizer. A selected step uses a
specialization of the same native update helper, captures register values at the
moment store, and performs two small indexed snapshots. The optimizer's existing
FT traversal performs a binary search in the sample index list per element on
selected steps; this cost is not proportional only to sample size. There is no
additional full-FT scan. Device storage is 56 bytes per sample plus a dummy half;
the host reads 52 bytes per sample and synchronizes the compute stream only on
selected steps. Use sparse step lists, not every training step. No throughput
overhead bound is claimed without measurement at the intended width/batch/backend.
Enabling the diagnostic also synchronizes the CUDA context once during diagnostic
buffer setup, so default-stream initialization finishes before compute uses it.

## Moment counters and denominators

`m` and `v` each refer to one store per sampled FT element. `old` is the previous
stored value, `candidate` is the scaled FP32 value before the storage cap, and
`stored` is the value actually stored. With FP32 state, the scale is 1 and no
FP16 cap is applied. Error sums are reported in **unscaled moment units**;
subnormal classification refers to the scaled half storage representation.

| Field | Meaning / rate denominator |
|---|---|
| `samples` | All sampled element stores in this row group |
| `nonfinite` | Any of old/candidate/stored is nonfinite; denominator `samples` |
| `finite` | All three are finite; denominator for general finite-store rates |
| `input_zero`, `input_nonzero` | Candidate is zero/nonzero; denominator `finite` |
| `zeroed` | Nonzero candidate becomes stored zero without cap; denominator `input_nonzero` |
| `capped` | m exceeds ±65504, or v exceeds +65504, before FP16 storage; denominator `finite` |
| `changed_candidate` | Candidate differs numerically from old; denominator `finite` |
| `round_to_same` | Changed candidate stores the old nonzero value, without cap; denominator `changed_candidate` |
| `stored_zero` | Stored value is zero; denominator `finite` |
| `stored_subnormal` | Half storage is nonzero with magnitude below 2^-14; denominator `finite` |
| `uncapped_nonzero` | Finite, uncapped, nonzero candidates; relative-error denominator |
| `uncapped_abs_error_sum`, `uncapped_abs_error_max` | Absolute error excluding caps; mean denominator `finite - capped` |
| `uncapped_relative_error_sum` | Sum of abs(stored-candidate)/abs(candidate), excluding zeros and caps; mean denominator `uncapped_nonzero` |
| `total_abs_error_sum` | Absolute storage error including caps; mean denominator `finite` |

Do not divide by a zero denominator. Nonfinite cases are counted separately and
excluded from all error sums. Zero sign is ignored. A cap is detected by the
pre-cap value, not merely a stored endpoint. `round_to_same` deliberately excludes
zeroing and cap events; its denominator still includes all changed candidates.
The finite categories partition the observations only where explicitly stated.

`input_zero` and `stored_zero` are not underflow counts. Neither implies that a
feature has never appeared. `zeroed` identifies loss at this particular storage
conversion; it does not diagnose information already lost during gradient or
FP32 arithmetic. `optimizer_gradient_nonzero` and `optimizer_gradient_nonfinite`
use `sampled_elements` as their denominator and describe the gradient consumed
by the optimizer. Norm loss modifies the master directly and is not included in
this gradient. Zero gradient does not establish feature absence: activity,
cancellation and clipping differ.
There is no historical feature-frequency counter.

## Master and forward copy

Each delta object has `samples`, `finite`, `changed`, `abs_delta_sum` and
`abs_delta_max`. `finite` means both endpoints are finite; divide `changed` and
the sum by `finite` for the change fraction and mean absolute update. Nonfinite
endpoints are `samples - finite`. Equality is numeric (zero sign is ignored).

- `master_optimizer`: FP32 master immediately before/after its optimizer update,
  including weight decay and clamping, before Lookahead.
- `master_norm_loss`: FP32 master before norm-loss correction versus before the
  optimizer update (zero when norm loss is disabled).
- `master_end_of_step`: master before norm-loss correction versus its value after
  the optimizer and Lookahead.
- `forward_fp16`: actual base-row forward buffer before the optimizer versus after
  Lookahead and factorizer fold. With factorization this is the folded base+virtual
  value; it is not the cast of the base master alone. Virtual rows have no separate
  forward buffer and their forward sample count is zero. Without an FP16 forward
  buffer, both groups' forward sample counts are zero.

The complete-step before-master boundary is before norm-loss weight correction.
A changed
master with an unchanged forward copy is possible and does not mean that the
FP32 master update disappeared. Row-group averages alone cannot attribute a
folded-forward change to a base or virtual update, and none of these diagnostics
establishes a playing-strength effect.
